## 1. 项目背景与目标

### 1.1 任务书要点提炼

任务书对本期工作提出了四类要求：

1. **算法链路**：SFM + MVS 完整流程 —— SIFT 特征 → KNN 匹配 → 8 点法 + RANSAC 剔除误匹配 → F 矩阵与 E 矩阵估算 → 分解 E 得到 R、t → 三角化 → PnP 注册新图 → BA 优化 → 外点剔除 → 稠密重建。
2. **工程底座**：OpenCV 源码编译并完成 CUDA 配置；Eigen、Ceres/g2o、PCL/VTK 等依赖打通；能搭建并运行原型系统。
3. **可视化交互**：给定图像 → 计算三维点云 → 三维交互展示。
4. **过程性成果**：可行性研究（多方案对比选优）、需求分析与详细定义、团队分工说明、阶段报告与答辩。

### 1.2 本期（3 周）目标

用一句话定义可验收的成果：

> 在一台带 NVIDIA 显卡的 Windows 工作站上，通过**一条命令或一个 GUI 操作**，把一组普通相机拍摄的、无序或有序的图像，自动重建出**稀疏点云 + 相机位姿 + 稠密点云**，并用 PCL/VTK 窗口完成**旋转、缩放、量测、导出**的交互查看，全过程有可复现的耗时与精度指标输出。

### 1.3 范围边界

**纳入范围（In Scope）**

- 单机离线处理，单场景重建（不要求实时、不要求联网、不要求多用户）。
- 标定内参已知或由标定流程产出（本期不做完全未知内参的稳健自标定）。
- 有序/无序图像序列均可输入；规模目标 10–50 张。
- 稀疏重建（增量式 SfM）+ 简化稠密重建（基于已知位姿的立体匹配/深度图融合）。
- 桌面端交互可视化与结果导出。

**明确排除（Out of Scope）**

- 移动端 / Web 端 / 云端部署；多用户并发与权限体系。
- 实时视频流重建、SLAM 式在线建图。
- 大规模场景（数百至数千张图）与分布式计算。
- 商业级网格后处理（纹理贴图、UV 展开、精细修补）。
- 深度学习特征/MVS（可作为后续工作提及，本期不实现）。

> 排除项需要在阶段报告"未来工作"中说明，答辩时主动交代边界，避免被追问时失分。

| --- | --- | --- | --- |
| FR-M2-01 | 图像序列读取：按文件名自然排序（`img_2` 在 `img_10` 之前），统一转灰度，支持 jpg/png，限制最大边长（默认 1600 px）以控制内存 | 50 张 12MP 图读取 ≤ 20 s，内存峰值 ≤ 2 GB | P0 |
| FR-M2-02 | 内参来源与校验：支持标定文件（fx, fy, cx, cy, k1, k2, p1, p2）与 EXIF 焦距推断；内参缺失时给出明确提示；校验内参与图像分辨率一致 | 分辨率与内参不匹配时报错而非静默出错 | P0 |
| FR-M2-03 | SIFT 特征提取：OpenCV `SIFT`，可配置 `nfeatures`、对比度阈值；CUDA 可用时走 `cv::cuda::SIFT` | 单张 1600px 图 ≤ 0.3 s（GPU）/ ≤ 1.0 s（CPU）；特征数默认上限 8000 | P0 |

### 3.3 M3 特征匹配与几何验证（P0）

**目标**：产出"几何上可信"的匹配关系，这是后续所有精度的地基。任务书明确要求"掌握 8 点法以及 RANSAC 实现去除错误匹配"。

| 编号 | 需求描述 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-M3-01 | KNN 匹配：`k=2` 的暴力/FLANN 匹配 + Lowe ratio test（默认 0.75），支持 GPU 描述子匹配 | 匹配耗时、匹配对数可输出；ratio 阈值可配 | P0 |
| FR-M3-02 | **自实现 8 点法**：归一化 DLT（Hartley 归一化）估计基础矩阵 F | 与 `cv::findFundamentalMat(FM_8POINT)` 在同一数据上 F 矩阵相对误差 < 5% | P0 |
| FR-M3-03 | **自实现 RANSAC**：随机采样 8 点、Sampson 距离阈值（默认 1.5 px）判内点、迭代上限与自适应停止 | 与 OpenCV RANSAC 内点集合 IoU ≥ 0.9；剔除误匹配后内点率提升可量化 | P0 |
| FR-M3-04 | 视图图构建：每张图连接共视最强的 k 个邻居（默认 k=10），记录内点数、内点率，低于阈值（默认 30 对）的边被剪除 | 输出 `view_graph.json`；孤立图像被标记并提示 | P0 |
| FR-M3-05 | 匹配可视化：并排连线图，内点绿/外点红，可导出 PNG 用于报告插图 | 任意匹配对可出图，命令行指定 pair id | P1 |

**关键风险**：平面场景导致 F 矩阵退化（单应性主导）。**缓解**：检测 H 内点与 F 内点比例，H 明显占优时标记该对为"退化对"，不予采用（该项同时服务 FR-M4-01）。

### 3.4 M4 增量式 SfM（P0，核心模块，10 人日）

**目标**：从匹配关系恢复相机位姿与稀疏三维结构。这是任务书算法要求的主体，也是评分最集中的部分。

| 编号 | 需求描述 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-M4-01 | 初始化像对选择：遍历视图图的边，综合内点数、基线估计（三角化视差中位数）与退化检测（H/F 内点比），选取得分最高的一对 | 3 组样例数据均能自动选出合理初始对，无需人工指定 | P0 |
| FR-M4-02 | 本质矩阵估计：`E = Kᵀ F K`，SVD 将奇异值强制为 (σ, σ, 0)，再分解得到 R、t 的 4 组候选解 | 分解结果满足 `RᵀR = I`、`det(R) = 1`；\|t\| 归一化为 1 | P0 |
| FR-M4-03 | 四解选优：对 4 组 (R, t) 三角化全部匹配点，选择"两相机前方点数最多"的解（cheirality check） | 选优正确率 100%（可用合成数据验证） | P0 |
| FR-M4-04 | 三角化：线性三角化（DLT，SVD 求解），剔除负深度点、视差角 < 1° 的点、重投影误差 > 4 px 的点 | 合成数据下三角化相对误差 < 1% | P0 |
| FR-M4-05 | PnP 注册新图：2D-3D 对应 → `solvePnPRansac`（EPnP 初值 + 迭代精化），内点 < 20 或内点率 < 30% 判定注册失败 | 30 张样例中注册成功率 ≥ 90% | P0 |
| FR-M4-06 | 增量注册循环：按"与已注册图像的共视点数"选下一张 → PnP 注册 → 三角化新增点 → 触发局部 BA（M5）→ 重复直至无图可注册 | 全流程无人工干预跑完 50 张图；日志显示每步选图依据 | P0 |
| FR-M4-07 | 中间结果序列化：每轮注册后写 `reconstruction.json`（相机内参/位姿、3D 点、观测、描述子索引），支持从断点续跑 | 中断后 `--resume` 从最近状态继续，结果与不中断一致 | P0 |
| FR-M4-08 | 轨迹与结构回读校验：重新加载结果后，重投影误差统计与保存前一致 | 回读前后指标差异 < 1e-6 | P1 |

**算法实现约束**：
- 位姿、3D 点统一使用 `double`，矩阵用 Eigen，避免手写矩阵乘。
- 每次会话固定随机种子（`--seed`），保证同参数同数据结果可复现。
- 关键步骤（F/E/三角化/PnP）必须能单独通过单元测试（见 NFR-TEST-01）。

### 3.5 M5 光束法平差 BA（P0）

**目标**：把"能跑"提升到"精度可看"，为优秀档提供可量化的优化证据。

| 编号 | 需求描述 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-M5-01 | 求解器封装：以 Ceres 为主（默认），预留 g2o 适配层；参数块为位姿（so3 + t，6 维）与 3D 点（3 维），内参默认固定 | 同一问题两种求解器结果重投影误差差异 < 5% | P0 |
| FR-M5-02 | 局部 BA（滑窗：当前帧 + 共视最强的若干帧 + 其可见点）与全局 BA 两级策略 | 30 张图全局 BA 单次 ≤ 60 s | P0 |
| FR-M5-03 | 鲁棒核：Huber（默认 δ=1 px）/ Cauchy 可选，抑制外点对解的拉扯 | 加入 5% 人工外点后，优化结果偏差 < 1 px | P0 |
| FR-M5-04 | 外点剔除：BA 后按重投影误差（默认 > 2 px）与卡方检验剔除观测；观测数 < 2 的 3D 点删除 | 迭代 2 轮后重投影 RMSE 单调下降并收敛 | P0 |
| FR-M5-05 | 优化日志与曲线：每次 BA 输出迭代次数、初始/终止代价、耗时，写入 `ba_log.csv` | Python 脚本可绘出代价下降曲线，用于报告 | P0 |
| FR-M5-06 | 内参自标定 BA：将 fx, fy, cx, cy 及径向畸变 k1, k2 加入参数块做联合优化 | 样例数据上内参收敛且不劣化重投影误差 | P2 |

### 5.2 使用场景

#### SC-01 环境搭建与自检（R1，一次性 / 换机器时）

- **触发**：拿到新工作站或重装系统。
- **前置**：已装 VS2022、CUDA Toolkit、CMake。
- **主流程**：克隆仓库 → 按 `docs/env.md` 编译 OpenCV（CUDA）→ `build.ps1` 构建主工程 → 运行 `check_env.exe` → 跑 `tests/` 单元测试 → 跑 10 张图的最小样例。
- **异常流**：CUDA 检测失败 → 提示算力与 `CUDA_ARCH_BIN` 不匹配；OpenCV 找不到 → 提示设置 `OpenCV_DIR`；测试失败 → 输出失败用例与日志。
- **成功判据**：30 分钟内完成，体检报告全绿，最小样例重建成功。

#### SC-02 单场景离线重建（R1/R2，日常主场景）

- **触发**：拿到一组新图像与内参。
- **前置**：图像目录、`camera.yaml`、可选标定文件。
- **主流程**：配置数据集 → 特征提取（命中/未命中缓存）→ 匹配与几何验证 → 初始化像对 → 增量注册 + 局部 BA → 全局 BA → 输出稀疏结果与指标。
- **异常流**：内参缺失 → 报错并提示先跑标定；注册率 < 50% → 建议提高重叠度或调整 ratio/RANSAC 阈值；某张图失败 → 记录并继续。
- **成功判据**：注册率 ≥ 90%，重投影 RMSE ≤ 1.0 px，全流程 ≤ 10 min。

#### SC-03 交互查看与量测（R3/教师/评委，演示场景）

- **触发**：重建完成，需要查看与讲解。
- **前置**：已有 PLY + 位姿 JSON。
- **主流程**：打开可视化程序 → 加载点云 → 旋转/缩放观察 → 切换相机位姿与轨迹 → 拾取两点量测距离 → 截图/导出。
- **异常流**：点云过大卡顿 → 自动提示降采样；文件格式不支持 → 明确报错并列出支持格式。
- **成功判据**：加载 ≤ 3 s，交互 ≥ 30 FPS，量测误差 < 2%，全程无卡死。

#### SC-04 批量实验与指标对比（R4/R2，写报告时）

- **触发**：需要消融实验与参数敏感性分析。
- **前置**：多组配置 yaml。
- **主流程**：批量脚本遍历配置 → 每次运行写 `metrics.json` → 汇总 CSV → Python 出图 → 报告中引用。
- **异常流**：某次运行失败 → 汇总表标记 FAIL，不中断其余实验。
- **成功判据**：一条命令产出全套对比图表，结论可量化。

#### SC-05 答辩现场演示（R1/R3，8–10 分钟）

- **触发**：答辩环节。
- **前置**：演示数据、预渲染视频、离线环境（无网络、可能无 GPU）。
- **主流程**：讲方案对比 → 播放/现场跑一遍缩短版流程（10 张图）→ 打开交互界面展示稠密点云与相机轨迹 → 展示精度与耗时对比表。
- **异常流**：现场机器无 CUDA → 切 CPU 配置（已预演）；程序异常 → 播放预录视频兜底。
- **成功判据**：8 分钟内讲完，演示无中断，能回答"为什么选 Ceres 不选 g2o""8 点法为何要归一化"等追问。

#### SC-06 新数据 / 新硬件接入（R4，P1）

- **触发**：老师提供新数据集或组内自采新场景。
- **前置**：仅有图像，无内参。
- **主流程**：跑标定流程 → 生成内参 → 配置数据集 → 走 SC-02。
- **异常流**：图像模糊/重叠不足 → 采集质量检查工具给出不合格原因。
- **成功判据**：非原开发者也能在 1 小时内完成接入。

## 8. 假设、依赖与风险

### 8.1 假设

1. 至少一台机器具备 NVIDIA 显卡（算力 ≥ 6.1）且可安装 CUDA Toolkit。
2. 验收数据以中等规模（10–50 张）、纹理丰富、重叠充分的场景为主。
3. 内参可由标定获得，或随数据集提供。
4. 组员具备 C++/OpenCV 基础，能在第 1 周内完成环境搭建。

### 8.2 外部依赖

| 依赖 | 版本建议 | 风险 |
| --- | --- | --- |
| OpenCV（源码） | 4.8–4.10 + CUDA | 编译耗时长（1–2 h），需预留时间 |
| Eigen | 3.4 | 与 PCL/Ceres 版本冲突 |
| Ceres Solver | 2.1–2.2 | Windows 下 SuiteSparse 依赖麻烦 |
| g2o | 最新 master | 备选方案，编译亦需 Eigen |
| PCL / VTK | 1.13 / 9.x | 安装包大，Qt 依赖需注意 |
| CUDA Toolkit | 11.8 或 12.x | 与 VS2022 版本强相关 |

### 8.3 风险与预案

| 风险 | 概率 | 影响 | 预案 |
| --- | --- | --- | --- |
| OpenCV CUDA 编译失败 | 中 | 高（P0 卡死） | 第 1 天优先做；先用官方预编译版跑通链路，并行修编译；CPU 路径必须完整 |
| Ceres 编译受阻 | 中 | 中 | 切 g2o；或在报告中说明并采用 g2o 作为主方案 |
| MVS 效果不达预期 | 高 | 中 | 退化为单对立体匹配；用 Open3D/COLMAP 结果做对照说明 |
| VTK 交互在演示机卡顿 | 中 | 高（现场失分） | 预先降采样演示数据；准备录屏兜底 |
| 人力不足/进度落后 | 中 | 高 | 按优先级砍 P1/P2；P0 保底清单见 3.0 节 |
| 数据采集失败（重叠不足/模糊） | 中 | 中 | 采集现场用 FR-M9-03 检查；备用公开数据集 |
